FIXING: ModuleNotFoundError scipy._lib.array_api_compat.numpy.fft
================================================================================

WHAT IS THIS ERROR?
================================================================================

When you run the .exe and get this error:

  ModuleNotFoundError: No module named 'scipy._lib.array_api_compat.numpy.fft'

This means PyInstaller didn't include all the scipy hidden dependencies when
it built your .exe file. This is a common issue with scikit-learn + scipy.

WHY DID THIS HAPPEN?
================================================================================

PyInstaller automatically detects most imports, but scipy has deeply nested
internal dependencies that PyInstaller's auto-detection misses.

The solution: Use our pre-configured spec file which includes ALL necessary
hidden imports for scipy, numpy, and scikit-learn.


SOLUTION 1: USE THE AUTOMATED BATCH FILE (EASIEST)
================================================================================

We've created build_exe.bat to automate the entire process with all fixes.

Steps:
  1. Open Command Prompt
  2. Navigate to your project folder:
     > cd C:\path\to\Register_Chatbot
  3. Run the build script:
     > build_exe.bat
  4. Wait for it to complete (takes 2-5 minutes)
  5. Your fixed .exe will be in the dist\ folder

That's it! The .exe will now work properly.


SOLUTION 2: REBUILD WITH SPEC FILE (MANUAL)
================================================================================

We've also included RegistrarChatbot.spec which has all the needed imports.

Steps:
  1. Delete previous builds:
     > rmdir /s /q dist
     > rmdir /s /q build
  2. Rebuild using the spec file:
     > pyinstaller RegistrarChatbot.spec
  3. Your fixed .exe will be in dist\RegistrarChatbot.exe


SOLUTION 3: ALTERNATIVE COMMAND LINE
================================================================================

If the spec file doesn't work, try this direct command:

  > pyinstaller --onefile --console ^
    --hidden-import=sklearn ^
    --hidden-import=scipy ^
    --hidden-import=numpy ^
    --hidden-import=scipy._lib ^
    --hidden-import=scipy._lib._array_api ^
    --hidden-import=scipy.sparse ^
    --hidden-import=scipy.sparse._sputils ^
    --hidden-import=scipy._lib.array_api_compat ^
    --hidden-import=scipy._lib.array_api_compat.numpy ^
    --hidden-import=scipy._lib.array_api_compat.numpy.fft ^
    --name RegistrarChatbot app.py

Note: This is very long; copy-paste it carefully or use Solution 1 or 2 instead.


PREVENT THIS ERROR IN THE FUTURE
================================================================================

To avoid this error:

1. Always use the RegistrarChatbot.spec file when building
   > pyinstaller RegistrarChatbot.spec

2. Or use the automated build script:
   > build_exe.bat

3. Don't use simple one-line PyInstaller commands like:
   > pyinstaller --onefile app.py
   (This won't include hidden dependencies)

WHY IS THE FIX FILE SO LARGE?
================================================================================

With scikit-learn and scipy included, your .exe will be 300-500 MB.

This is NORMAL because:
- scikit-learn is a large library (~50 MB)
- scipy with all modules is ~100 MB
- numpy adds another ~50 MB
- Plus the Python runtime and dependencies

Size is not a problem:
- It's still one single .exe file
- No installation needed on user's machine
- Performance is unaffected
- Disk space is cheap

NOTES FOR DEVELOPERS

The RegistrarChatbot.spec file includes these hidden imports:

Core Dependencies:
  - numpy.core._multiarray_umath

SciPy Modules (the problematic ones):
  - scipy._lib._array_api
  - scipy._lib.array_api_compat.numpy
  - scipy._lib.array_api_compat.numpy.fft (this was the missing one!)
  - scipy._lib.array_api_compat.numpy.linalg
  - scipy.sparse._sputils

scikit-learn Modules:
  - sklearn.feature_extraction.text
  - sklearn.metrics.pairwise
  - (+ base modules)

When you update scikit-learn or scipy, you may need to update the spec file
with additional hidden imports if new internal dependencies are added.
